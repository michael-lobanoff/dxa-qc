# DXA QC — контроль качества денситометрических исследований

Сервис проверяет DICOM-снимки денситометрии (DXA) поясничного отдела позвоночника и проксимального
отдела бедра: пригоден ли снимок для интерпретации, и если нет — какое нарушение найдено и почему
(в градусах и миллиметрах). Работает локально, без обращения к внешним сервисам.

> Статус: рабочий черновик (MVP). Метрики и ограничения — в `docs/night_report.md`.

## Как это работает

```
DICOM → чтение и нормализация → область (позвоночник / левое / правое бедро)
      → ключевые точки (U-Net) → измерения → решения по типам нарушений → строка отчёта
```

| Нарушение | Как определяется |
|---|---|
| Наклон оси позвоночника | угол линии «середина столба сверху — на уровне таза» к вертикали |
| Некорректная укладка позвоночника | сеть не видит гребни подвздошных костей в кадре; сверху — охват меньше 3.2 высот позвонка над линией гребней (ТЗ: до середины Th12) |
| Инородные тела | тонкие яркие структуры (морфологический top-hat) вне позвоночного столба |
| Поля вокруг области интереса бедра | расстояния от головки и малого вертела до краёв кадра, мм |
| Позиционирование / ротация бедра | HOG-признаки выровненного по точкам участка + случайный лес |

Каждый тип — маленькая монотонная модель по 1–3 измерениям с калибровкой и собственным порогом.

### Рабочая точка

Вердикт по снимку ставится по общей вероятности (noisy-OR по типам), а не по правилу «сработал хотя бы
один тип»: при 6–36 нарушениях на тип пороги отдельных типов нестабильны, и их объединение даёт худший
результат. Порог выбирается по целевой чувствительности; политика переключается переменной `DXAQC_POLICY`:

| Политика | ROC-AUC | F1 | Чувств. | Специф. | Когда |
|---|---|---|---|---|---|
| `screening` (по умолчанию) | 0.825 | 0.642 | 0.82 | 0.69 | не пропустить брак; лаборант перепроверяет укладку сразу |
| `balanced` | 0.825 | 0.627 | 0.76 | 0.72 | порог по максимуму F1 |
| старое правило «сработал тип» | 0.825 | 0.629 | 0.62 | 0.86 | — |

Если снимок помечен по общей вероятности, но ни один тип не перешёл свой порог, в отчёте указывается
наиболее вероятная причина и пометка «тип указан как наиболее вероятный».

## Структура

```
dxaqc/            пакет сервиса
  service.py      сервис: DICOM → результат (QCService, read_dicom_image)
  batch.py        пакетная обработка папки / zip (общая для CLI и API)
  api.py          HTTP API (FastAPI)
  visualize.py    визуализация нарушения: PNG + DICOM Secondary Capture
  sr.py           текстовый отчёт о нарушениях: DICOM Basic Text SR
  region.py       классификатор области по содержимому
  kpmodel.py      сеть ключевых точек, аугментации, декодирование
  detector.py     обёртка для инференса точек
  geometry.py     правила по точкам (наклон, поля, охват)
  pixels.py       размер пикселя из DICOM (Exposed Area) с проверкой правдоподобия
  vertebrae.py    поиск тел позвонков: шаг позвонка как анатомическая линейка
  features.py     измерения по точкам бедра
  hipcrop.py      выравнивание участка бедра по точкам
  artifacts.py    признаки инородных тел
  decision.py     решения по типам нарушений
  synth.py        генератор синтетических нарушений
scripts/          обучение, оценка, пакетная обработка (predict.py)
tools/annotator   локальный инструмент разметки точек; tools/viewer — обзор разметки
docs/             схема и инструкция разметки, отчёты
models/           веса и модели (kp_spine.pt, kp_hip.pt, region.pkl, decision.pkl)
```

## Системные требования

Замер на 499 снимках (архив организаторов, MacBook M1 Pro): только процессор — 0.13 с на снимок, пик памяти 0.9 ГБ;
с GPU (Apple MPS) — 0.05 с, 0.6 ГБ. Вердикты на CPU и GPU совпадают полностью. Модели — 60 МБ.

| | Минимальная | Рекомендуемая |
|---|---|---|
| CPU | 2 ядра x86-64 / arm64 | 4+ ядер |
| RAM | 2 ГБ | 4 ГБ |
| GPU | не нужен | любой CUDA-GPU (ускоряет в 2–3 раза) |
| Диск | 1 ГБ (CPU-сборка) | 6 ГБ (сборка с CUDA) |

Устройство выбирается автоматически (CUDA → MPS → CPU); принудительно: `DXAQC_DEVICE=cpu|cuda|mps`.
Лимит ТЗ — 3 минуты на исследование; фактически — доли секунды.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/pip install -e .
.venv/bin/python scripts/predict.py <папка_или_архив.zip> --out outputs/results.csv
```

Docker:

```bash
docker build --platform linux/amd64 -t dxa-qc .
docker run --rm -v /path/to/studies:/data -v $PWD/outputs:/out dxa-qc /data --out /out/results.csv
```

## HTTP API

```bash
.venv/bin/uvicorn dxaqc.api:app --host 0.0.0.0 --port 8000
# в Docker: docker run --rm -p 8000:8000 -v /path/to/studies:/data -v $PWD/outputs:/out --entrypoint uvicorn dxa-qc dxaqc.api:app --host 0.0.0.0 --port 8000
```

| Метод | Что делает |
|---|---|
| `GET /health` | статус и список загруженных моделей |
| `POST /predict?format=json\|csv\|xlsx\|zip` | multipart `files`: DICOM-файлы или один .zip; `zip` — таблица + визуализации |
| `POST /predict_folder` | `{"input": "/data", "output": "/out/results.csv", "vis": true}` — пакетная обработка смонтированной папки; пути только внутри `DXAQC_ALLOWED_ROOTS` (по умолчанию `/data`, `/out`, рабочая папка) |

Документация OpenAPI: `http://localhost:8000/docs`.

## Формат результата

CSV (UTF-8 с BOM) и XLSX, одна строка на изображение:

| Колонка | Описание |
|---|---|
| path_to_study | папка исследования во входных данных |
| study_uid, image_uid | StudyInstanceUID, SOPInstanceUID |
| anatomical_region | определённая область |
| quality_class | 0 — качественное, 1 — есть нарушение |
| violation_type | перечень нарушений через «; » |
| processing_status | Success / Failure |
| time_of_processing | секунды |
| quality_score | вероятность нарушения (для ROC-AUC) |
| violation_codes | коды нарушений (v_axis, v_pos, v_artifact, v_roi, v_posrot, implant) |
| details | измерения: наклон оси, охват в позвонках, поля кадра в мм; пометка о наиболее вероятном типе |
| mm_per_px, mm_per_px_source | размер пикселя и откуда он взят (`ExposedArea` / `default`) |
| error | текст ошибки для Failure |

## Тесты

```bash
.venv/bin/pip install pytest && .venv/bin/python -m pytest -q tests
```

## Воспроизведение обучения

```bash
python scripts/build_index.py                    # индекс снимков и меток, дедупликация
python scripts/train_keypoints.py --region spine # CV + финальная модель точек
python scripts/train_keypoints.py --region hip
python scripts/fit_decision.py                   # решающий слой на OOF-признаках
python scripts/eval_pipeline.py                  # сквозные метрики с 95 % ДИ
```

Разметка точек: `data/train/keypoints.json` (схема — `docs/annotation_scheme.md`).

## Известные ограничения

- Обучено на 100 исследованиях одного аппарата (GE Lunar Prodigy Advance).
- Размер пикселя: тега PixelSpacing нет, берётся из Exposed Area (0040,0303) — 0.60–0.64 мм/пикс,
  подтверждено двумя анатомическими линейками (шаг позвонков 30 мм, головка бедра 40 мм). Там, где в теге
  записана площадь всего стола (104 снимка из 252), используется значение по умолчанию 0.607 мм/пикс.
- Бёдра с эндопротезом не оцениваются (quality_class 0, код implant) — формат вывода согласуется с организаторами.
- «Сколиоз» без типа нарушения в разметке эксперта сервисом не выявляется.
- Верхний охват позвоночника (Th12) — в обучающих данных нет ни одного подтверждённого нарушения этого типа,
  поэтому правило намеренно консервативно: срабатывает только при охвате меньше 3.2 высот позвонка
  (у всех наших снимков 3.5 и больше).
- Уровни позвонков не нумеруются: на DXA без рёбер нумерация неоднозначна. Ось строится по двум точкам —
  ось по средним линиям позвонков оказалась заметно хуже (AUC 0.57 против 0.89).
