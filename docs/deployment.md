# Руководство по развёртыванию

Сервис работает локально и не обращается к внешним сервисам: ни изображения, ни метаданные никуда
не уходят. Интернет нужен только один раз — при сборке образа (скачивание зависимостей).

## Требования

| | Минимально | Рекомендуется |
|---|---|---|
| CPU | 2 ядра x86-64 или arm64 | 4+ ядер |
| RAM | 2 ГБ | 4 ГБ |
| GPU | не нужен | любой CUDA-GPU (ускоряет в 2–3 раза) |
| Диск | 3 ГБ под образ | 8 ГБ при сборке с CUDA |
| ОС | Linux / macOS с Docker | — |

Фактическая скорость: 0.13 с на снимок на процессоре, 0.05 с с GPU, пик памяти 0.9 ГБ.
Лимит ТЗ — 3 минуты на исследование.

## Сборка образа

```bash
docker build --platform linux/amd64 -t dxa-qc .
```

Образ — 1.69 ГБ. Две особенности, заложенные в `Dockerfile`:

- torch ставится **CPU-сборкой** с `https://download.pytorch.org/whl/cpu`. Обычное колесо тянет весь
  стек CUDA (~2.5 ГБ) — сборка от этого падала по таймауту, а сервису GPU не нужен. Для сборки под
  GPU замените индекс на `https://download.pytorch.org/whl/cu124`;
- `--platform linux/amd64` указывается явно, если собираете на Apple Silicon, иначе получится образ
  под arm64, который не запустится на x86-сервере.

Проверка образа:

```bash
docker run --rm dxa-qc --help
```

## Запуск

### Пакетная обработка папки

```bash
docker run --rm \
  -v /path/to/studies:/data:ro \
  -v /path/to/output:/out \
  dxa-qc /data --out /out/results.csv --vis /out/vis
```

Входная папка монтируется только на чтение. На выходе `results.csv`, `results.xlsx`, папка `vis`
с картинками и архив `results_vis.zip`.

### HTTP API и веб-интерфейс

```bash
docker run --rm -p 8000:8000 \
  -v /path/to/studies:/data:ro -v /path/to/output:/out \
  --entrypoint uvicorn dxa-qc dxaqc.api:app --host 0.0.0.0 --port 8000
```

- `http://localhost:8000/` — веб-интерфейс;
- `http://localhost:8000/docs` — описание методов (OpenAPI);
- `http://localhost:8000/health` — проверка живости: отвечает `{"status": "ok"}` и списком моделей.

Проверка после запуска:

```bash
curl -s localhost:8000/health
curl -X POST "localhost:8000/predict?format=csv" -F "files=@sample.dcm" -o out.csv
```

### Без Docker

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install -e .
.venv/bin/python scripts/predict.py <папка> --out results.csv
```

Нужен Python 3.11+. Веса моделей лежат в `models/` (60 МБ) и входят в репозиторий.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DXAQC_MODELS` | папка с весами | `models` (в образе `/app/models`) |
| `DXAQC_DEVICE` | `cpu`, `cuda` или `mps` | автовыбор CUDA → MPS → CPU |
| `DXAQC_POLICY` | рабочая точка: `screening` (чувствительность) или `balanced` (максимум F1) | `screening` |
| `DXAQC_PIXEL_MM` | размер пикселя, `"x,y"` в мм — переопределяет значение из DICOM | из тега Exposed Area |
| `DXAQC_ALLOWED_ROOTS` | через `:` — папки, доступные методу `/predict_folder` | `/data:/out:$PWD` |

## Безопасность

- Внешних сетевых вызовов нет; при работе контейнер можно запускать с `--network none`
  (для пакетного режима; для API нужен проброс порта).
- `/predict_folder` принимает пути только внутри `DXAQC_ALLOWED_ROOTS` — иначе `403`.
- Имена файлов из загруженных архивов не используются как пути (защита от «zip slip»),
  кириллица в именах архива декодируется.
- Персональные данные из DICOM сервис не использует: область определяется по изображению.
  В выходной таблице остаются только `StudyInstanceUID` и `SOPInstanceUID`.

## Типовые проблемы

| Симптом | Причина и решение |
|---|---|
| Сборка падает на `pip install torch` по таймауту | тянется CUDA-колесо; проверьте, что в `Dockerfile` остался индекс `/whl/cpu` |
| `exec format error` при запуске | образ собран под другую архитектуру; пересоберите с `--platform linux/amd64` |
| Все строки `Failure` | входная папка смонтирована не туда; проверьте `-v ... :/data` и что путь в команде — `/data` |
| В отчёте `unsupported` | изображение не распознано как денситометрия позвоночника или бедра — проверьте, те ли файлы поданы |
| Кракозябры в именах файлов из архива | архив собран без UTF-8; сервис сам пробует cp866/cp1251, имена в отчёте будут читаемыми |
| Разные вероятности на разных машинах | сборки библиотек под arm64 и amd64 считают чуть по-разному (медиана 0.0015); вердикты совпадают в 98.6 % |

## Воспроизводимость

Повторный запуск на той же машине даёт идентичный результат: модели загружаются в режиме
инференса, случайности в предсказании нет. Версии всех зависимостей зафиксированы в
`requirements.txt`, базовый образ — `python:3.12.2-slim`.
