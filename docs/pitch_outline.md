# Содержание презентации (черновик)

Структура слайдов 7–11 задана шаблоном организаторов; ниже — материал по пунктам ТЗ (раздел 4) и
критериям оценки (раздел 8). Картинки лежат в `docs/figures/` и `docs/night/`.

## 1. Подход и его обоснование

- Критерии качества DXA **геометрические** (наклон ≤ 5°, охват Th12 → гребни, поля 3 см / 2 см, малый вертел).
  Поэтому ядро — **детектор анатомических точек**, а решения — измерения в градусах и мм, понятные врачу.
- Что нельзя измерить линейкой (ротация бедра, металл), решают модели по изображению участка.
- Каждое срабатывание объяснимо: картинка с точками, осью, полями и контуром металла (ТЗ 2.6).

## 2. Архитектура

`DICOM → нормализация → область (HOG + лог. регрессия) → точки (U-Net, 4 / 9 точек) → измерения
→ 5 типов нарушений (монотонные модели + лес для ротации) → CSV/XLSX + визуализация (PNG, DICOM SC)`.
Интерфейсы: CLI, HTTP API (FastAPI), Docker-образ 1.69 ГБ (linux/amd64, CPU-сборка torch).
Всё локально, без внешних сервисов и чужих весов.

## 3. Данные, разбиение, предобработка

- 100 исследований, 499 файлов, но **252 уникальных изображения** (побайтные дубли экспорта удалены).
- Метки эксперта — на исследование и область; перенесены на изображения по определённой области.
- Ключевые точки размечены нами (полуавтоматически + ручная проверка), вслепую относительно меток эксперта;
  проверка разметки человеком на 48 снимках, повторный замер головок (расхождение 6 px).
- **Разбиение по пациентам** (StratifiedGroupKFold, группы = исследование): оба бедра и позвоночник одного
  пациента всегда в одном фолде — **нет утечки**. 5 фолдов × 10 повторов, 95 % ДИ бутстрепом.
- Предобработка: MONOCHROME1, rescale, 16 бит → 8 бит, мультикадр; левые бёдра зеркалятся в правые.
- **Калибровка масштаба:** PixelSpacing в файлах нет, размер пикселя берётся из Exposed Area (0040,0303) —
  0.60–0.64 мм/пикс; подтверждён двумя анатомическими линейками (шаг позвонков 30 мм, головка бедра 40 мм).
  До этого использовалась оценка «на глаз» 0.8 — все расстояния были завышены на треть.

## 4. Таксономия и несколько нарушений

Коды: `v_axis` наклон оси, `v_pos` таз не в кадре, `v_artifact` инородные тела, `v_roi` поля кадра бедра,
`v_posrot` позиционирование / ротация бедра, `implant` не оценивается. Нарушения независимы
(multi-label): снимок «с нарушением», если сработал хоть один тип; вероятность — noisy-OR по типам.

## 5. Эксперименты и сравнение

- Ротация: геометрия 0.61–0.72 → HOG + лог. рег. 0.67 → CNN 0.73 → многозадачная сеть 0.69 → **HOG + лес 0.81**
  (`figures/rotation_approaches.png`). Вывод: на 150 снимках классика с правильным выравниванием сильнее нейросети.
- Артефакты: правило top-hat 0.90, сегментационная сеть на синтетике 0.89, вместе 0.91.
- Позвонки (отрицательный результат, показываем честно): ось по средним линиям тел позвонков — AUC 0.57
  против 0.89 у оси по двум точкам; на таком разрешении центр позвонка гуляет на 10–20 пикс. Зато шаг
  позвонков (30 мм) работает как линейка пациента и закрывает критерий ТЗ «сверху видна половина Th12»:
  охват меряется в позвонках (нужно ~4.5 над линией гребней), без зависимости от размера пикселя.
- Синтетические нарушения (наклон, обрезка, металл) — генератор с метками по тем же правилам, что и сервис.
- Дисбаланс классов (6–36 нарушений): веса классов, пороги по F1 внутри фолдов, монотонные модели,
  которые не могут выучить обратный знак на малых выборках.

«сработал хотя бы один тип». Переключается одной переменной окружения.

По типам нарушений: наклон оси 0.90, укладка позвоночника 0.88,
инородные тела 0.86, поля кадра бедра 0.91, ротация 0.87.

Детектор точек: медиана 0.6–6.4 мм в зависимости от точки (`figures/detector_errors.png`).

## 7. Анализ ошибок (`night/errors_*.png`)

- Наклон: ложные срабатывания — сколиоз; добавили признак кривизны → специфичность 0.83 → 0.89.
- Артефакты: пропуски — крючки и клипса у позвоночника; «ложные» — косточки, которые эксперт не отметил.
- Метки: 3 противоречия в разметке эксперта (сколиоз без типа, перелом) — показать честно.

## 8. Скорость и требования

0.05 с/снимок на GPU, 0.13 с на CPU, 0.6–0.9 ГБ памяти, модели 60 МБ; вердикты CPU и GPU совпадают.
Лимит ТЗ 3 мин — запас > 1000×.

## 9. Ограничения и внедрение

- Один аппарат (GE Lunar Prodigy) и 100 исследований — нужна донастройка на данных других аппаратов.
- Размер пикселя берётся из тега Exposed Area; у 104 снимков из 252 в теге площадь всего стола —
  для них берётся значение по умолчанию 0.607 мм/пикс (на аппаратах другого типа нужна проверка).
- Внедрение: пилот «второе мнение» у лаборанта сразу после скана → повторная укладка до ухода пациента;
  накопление подтверждённых врачом случаев → дообучение (инструменты разметки и обзора уже есть).

## 10. Демо-кейсы

Тестовые файлы организаторов: позвоночник с косточками белья (найден металл, показан контур), два бедра
с полями кадра в мм. Сценарий: `predict.py --vis` → таблица + zip с картинками; то же через `/predict?format=zip`.
