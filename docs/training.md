# Обучение и дообучение моделей

Всё обучение — на процессоре или одной видеокарте, целиком занимает около полутора часов.
Чужие предобученные веса не используются: все сети обучены с нуля на предоставленных данных.

## Что из чего состоит

| Модель | Файл | Что делает | Как обучена |
|---|---|---|---|
| Классификатор области | `models/region.pkl` | позвоночник / левое / правое бедро + проверка «свой-чужой» снимок | HOG + логистическая регрессия, 252 снимка |
| Точки позвоночника | `models/kp_spine.pt`, `_2`, `_3` | 4 точки: верх и низ столба, два гребня | ансамбль из трёх U-Net с нуля (разные зёрна и аугментации), тепловые карты усредняются |
| Точки бедра | `models/kp_hip.pt`, `_2`, `_3` | 9 точек: головка, шейка, вертелы, седалищная кость, диафиз | то же, левые бёдра зеркалятся в правые |
| Решающий слой | `models/decision.pkl` | вероятность каждого типа нарушения и вердикт | монотонные модели (для оси и полей кадра — с синтетикой) + лес для ротации по кропам всех членов ансамбля |
| Сегментация металла | `models/artifact_seg.pt` | контур инородного тела для картинки | U-Net на реальных боксах и синтетическом металле |

Тела позвонков (`dxaqc/vertebrae.py`) и правила по точкам (`dxaqc/geometry.py`) — детерминированные
алгоритмы, обучения не требуют.

## Данные

```
data/train/
  Исследования/<StudyInstanceUID>/…/*.dcm   выгрузка организаторов как есть
  разметка.xlsx                              экспертные метки: исследование × область
  image_index.csv                            строится скриптом: уникальные снимки, метки, размер пикселя
  keypoints.json                             наша разметка ключевых точек
data/annotation/images/<NNN>_<region>.png    те же снимки в PNG для инструментов разметки
```

Важные правила работы с метками:

- метки эксперта заданы **на исследование и область**, а не на файл; в одном исследовании до трёх
  изображений, дубликаты выгрузки удаляются по хешу пикселей (499 файлов → 252 уникальных снимка);
- метка снимка считается как «или» по столбцам конкретных нарушений: организаторы подтвердили, что
  в итоговом столбце их таблицы есть ошибки;
- разбиение всегда **по пациентам** (`StratifiedGroupKFold`, группа = исследование): оба бедра и
  позвоночник одного человека не могут оказаться по разные стороны от границы обучения и проверки.

## Порядок обучения

```bash
python scripts/build_index.py        # индекс снимков, метки, размер пикселя из DICOM     ~2 мин
python scripts/train_region.py       # классификатор области + проверка «свой-чужой»      ~1 мин
# три члена ансамбля детектора точек: 5 фолдов + финальная модель у каждого  ~20–60 мин на запуск
for r in spine hip; do
  python scripts/train_keypoints.py --region $r --aug fix    --seed 100 --tag fix_s100
  python scripts/train_keypoints.py --region $r --aug strong --seed 100 --tag strong_s100 --epochs 200
  python scripts/train_keypoints.py --region $r --aug base   --seed 100 --tag base_s100
done
# финальные модели -> models/kp_<region>.pt, kp_<region>_2.pt, kp_<region>_3.pt
python scripts/ensemble_oof.py --tags fix_s100 strong_s100 base_s100 --out ens3      # точки ансамбля вне фолдов
cp data/train/kp_oof_spine_ens3.json data/train/kp_oof_spine.json; cp data/train/kp_oof_hip_ens3.json data/train/kp_oof_hip.json
python scripts/synth_decision.py --tags fix_s100 strong_s100 base_s100 --name ens3 --no-eval   # синтетика ~15 мин
python scripts/train_artifact_seg.py --save-final   # сегментация металла                 ~30 мин
python scripts/fit_decision.py --synth ens3 --members fix_s100 strong_s100 base_s100          # ~3 мин
python scripts/eval_pipeline.py --synth ens3 --members fix_s100 strong_s100 base_s100         # ~5 мин
python scripts/figures.py            # графики для отчёта из сохранённых результатов      ~10 с
```

Ключевая деталь: `fit_decision.py` учится не на «идеальных» ручных точках, а на точках, предсказанных
моделями, которые этот снимок не видели (`data/train/kp_oof_*.json`). Поэтому калибровка и пороги
переносятся на новые данные, а не подстраиваются под разметку. Модели фолдов сохраняются в
`data/train/kp_folds/<tag>/`: они нужны, чтобы собрать точки ансамбля вне фолдов и измерить синтетику
детектором, который исходный снимок не видел.

Почему ансамбль, а не один детектор: два детектора с одинаковой ошибкой точек давали ротацию бедра
0.86 и 0.81 AUC — модель ротации читает кроп, выровненный по точкам, и чувствительна к тому, куда
именно детектор их поставил. Настройки, подобранные на одной реализации, частично подгоняются под
её ошибки. Новые настройки проверяются на реализации детектора, не участвовавшей в подборе.

## Как проверять, что стало лучше

```bash
python scripts/eval_pipeline.py      # AUC, F1, чувствительность, специфичность с доверительными интервалами
python scripts/eval_rules.py         # правила по точкам: ручные точки против предсказанных
python scripts/threshold_policy.py   # сравнение вариантов рабочей точки
python scripts/check_external.py data/external/<набор>   # поведение на чужих данных
```

Ориентир текущей версии: общий ROC-AUC 0.872 [0.82–0.92], F1 0.741 при чувствительности 0.83;
по исследованиям F1 0.819 при чувствительности 0.90.
Сравнивать имеет смысл только цифры из `eval_pipeline.py` — они получены на кросс-валидации
по пациентам, где все компоненты не видели проверяемый снимок.

## Дообучение на новых данных

1. Положите новые исследования в `data/train/Исследования/` и добавьте строки в `разметка.xlsx`
   (формат: одна строка на исследование, столбцы по областям и типам нарушений).
2. `python scripts/build_index.py` — индекс пересоберётся, дубликаты отсеются.
3. Разметьте ключевые точки на новых снимках: `python scripts/export_for_annotation.py`, затем
   локальный инструмент `tools/annotator/index.html` (схема — `docs/annotation_scheme.md`,
   иллюстрированная инструкция — `docs/annotation_guide.html`). Результат слить командой
   `python scripts/merge_keypoints.py --policy latest`.
4. Переобучите сети точек и решающий слой (шаги выше). Если новых снимков немного, достаточно
   `fit_decision.py`: решающий слой перенастроится под новое распределение без переобучения сетей.
5. Проверьте метрики `eval_pipeline.py` и сравните с прежними. Падение специфичности при росте
   чувствительности — обычно следствие смены рабочей точки, а не ухудшения модели: смотрите AUC.

**Аппарат другого производителя.** Классификатор области и проверка «свой-чужой» обучены на выгрузках
GE Lunar Prodigy. Проверьте новые снимки через `scripts/check_external.py`: если они массово
получают отказ «снимок не похож на денситометрию», добавьте их в обучение классификатора
(`train_region.py`) — этого достаточно, чтобы расширить область применимости.

## Новый тип нарушения

1. Добавьте столбец с меткой в `разметка.xlsx` и в `REGION_LABELS` в `scripts/build_index.py`.
2. Опишите тип в `TYPES` в `dxaqc/decision.py`: перечислите измерения и знак каждого
   (+1 — «чем больше, тем хуже»), добавьте формулировку в `NAMES_RU`.
3. Если нужного измерения ещё нет, добавьте его в `dxaqc/features.py` или `dxaqc/geometry.py`.
4. `python scripts/fit_decision.py && python scripts/eval_pipeline.py`.

Монотонные модели выбраны намеренно: при 6–36 примерах нарушения на тип обычная регрессия способна
выучить обратный знак на отдельном фолде, а модель с заданным направлением — нет.
