# Архитектура решения: модели, обучение, дообучение

Подробное техническое описание для критерия 8.2 ТЗ. Схемы к разделам собираются локально: `python scripts/figures_pitch.py` кладёт их в `docs/figures/`.
Команды обучения и порядок запуска — `docs/training.md`, результаты замеров — `docs/night_report.md`.

## 1. Конвейер целиком

```
DICOM
 └─ чтение и нормализация                               (без обучения, dxaqc/service.py, dxaqc/pixels.py)
     └─ [1] анатомическая область + «свой/чужой»        HOG + логистическая регрессия   (dxaqc/region.py)
         └─ [2] ключевые точки                          ансамбль из 3 U-Net             (dxaqc/kpmodel.py)
             ├─ измерения в мм и градусах               (без обучения, dxaqc/geometry.py, features.py)
             ├─ [3] сегментация металла                 U-Net, 1 канал                  (dxaqc/artifactnet.py)
             └─ [4] ротация бедра                       HOG кропа + ExtraTrees          (dxaqc/hipcrop.py)
                 └─ [5] пять решающих моделей           монотонные модели + калибровка  (dxaqc/decision.py)
                     └─ вердикт, типы нарушений, отчёт
```

Обучаемых компонентов пять; ещё два шага — чтение DICOM и измерения по точкам — детерминированные
и никакого обучения не требуют. Все веса обучены на данных организаторов, **чужие предобученные веса
не используются**: это важно и для воспроизводимости, и потому, что предобучение на ImageNet
проверяли — оно не помогло (`night_report.md`, раздел 17).

## 2. Модель 1 — анатомическая область и защита «свой/чужой»

| | |
|---|---|
| Файл | `dxaqc/region.py`, веса `models/region.pkl` (3.6 МБ) |
| Вход | снимок в оттенках серого, приводится к 128×128 |
| Признаки | HOG: ячейка 16 пикселей, 9 ориентаций, блоки 2×2 с L2-нормировкой |
| Модель | логистическая регрессия, `C = 0.1`, три класса: позвоночник / левое бедро / правое бедро |
| Аугментация | каждое изображение добавляется ещё и зеркально, с меной класса левого и правого бедра |
| Результат | 252 из 252 на кросс-валидации, 3 из 3 на тестовых файлах организаторов |

Поверх классификатора — три независимые проверки, что снимок вообще похож на денситометрию:

1. **новизна**: расстояние HOG-описания до банка обучающих описаний; порог 1.0 при максимуме 0.80
   на обучающих снимках;
2. **размер пикселя**: настоящий тег меньше 0.30 мм означает обычный рентген, а не денситометрию
   (у денситометра шаг детектора около 0.6 мм);
3. **размер изображения**: длинная сторона больше 1200 пикселей — то же самое, но работает и без тегов.

Не прошедший проверку снимок получает `quality_class 0`, код `unsupported` и причину отказа.
Проверено на 66 рентгенограммах поясничного отдела из набора LUMOS: отклонены все 66.

## 3. Модель 2 — ключевые точки (ядро решения)

| | |
|---|---|
| Файл | `dxaqc/kpmodel.py`, веса `models/kp_spine*.pt`, `models/kp_hip*.pt` (по 19 МБ) |
| Архитектура | U-Net: энкодер 32→64→128→256→256, декодер с тремя skip-связями |
| Параметры | 4.86 млн (позвоночник), 4.87 млн (бедро) |
| Вход | 1×256×256 плюс два координатных канала (нормированные x и y) |
| Выходы | тепловые карты 128×128 на каждую точку **и** логит «точка в кадре» из бутылочного горлышка |
| Точки | позвоночник — 4 (верх столба, столб на уровне таза, два гребня); бедро — 9 (головка ×2, шейка, большой вертел ×2, малый вертел, седалищная кость, диафиз ×2) |

**Почему две головы.** Тепловая карта отвечает «где точка», отдельный логит — «есть ли она в кадре
вообще». Это не украшение: «некорректная укладка позвоночника» по ТЗ — это когда гребни таза
не попали в кадр, то есть именно ответ второй головы и есть признак для типа нарушения.

**Функция потерь:** MSE по тепловым картам, усреднённая только по видимым точкам, с весом 100,
плюс 0.5 × бинарная кросс-энтропия по видимости.

**Обучение:** AdamW, `lr = 2e-3`, `weight_decay = 1e-4`, расписание OneCycle (10 % разогрева),
батч 8, 120 эпох (для уровня аугментаций `strong` — 200). Одна модель учится 20–60 минут на GPU
ноутбука.

**Аугментации** (`kpmodel.augment`): обрезка поля сверху и снизу, зеркальное отражение, аффинный
джиттер (сдвиг, поворот, масштаб), изменение яркости и контраста. Уровни `base` / `fix` / `strong`
различаются силой. В уровне `base` была ошибка: точка, ушедшая за край при обрезке, сохраняла
координаты и после вписывания в квадрат оказывалась в чёрной рамке — модель училась, что срезанные
гребни «видны». Исправлено в `fix`: такие точки помечаются как отсутствующие. Эффект измерен —
уверенность в срезанных гребнях упала с 0.41–0.98 до 0.07–0.23, точность «в кадре / вне кадра»
выросла с 95 % до 98 %.

**Декодирование:** субпиксельное — argmax по карте, затем взвешенный центроид в окне 5×5.

**Ансамбль из трёх.** В сервисе лежат три модели на область, обученные с разными аугментациями
и сидами (`fix_s100`, `strong_s100`, `base_s100`); усредняются тепловые карты и логиты видимости,
а не координаты. Для позвоночника дополнительно применяется зеркальное TTA: предсказание на
отражённом снимке усредняется с обычным (гребни меняются местами обратно).

**Зачем ансамбль.** Две сети с одинаковой средней ошибкой в пикселях давали ротацию бедра 0.86
и 0.81 AUC — то есть результат зависел от случайной реализации, а настройки подбирались под удачную.
Ансамбль эту зависимость убирает, и все метрики в отчёте сняты именно на нём. Проверяли и
ансамбли из четырёх и пяти — хуже (0.873 и 0.875 против 0.880 по AUC): разные реализации
сдвигают кроп бедра, и модель ротации теряет больше, чем выигрывает от усреднения точек.

**Точность точек** (вне обучающих фолдов, медиана): верх столба 0.9 мм, столб у таза 4.3 мм,
гребни 5.4–5.8 мм, малый вертел 1.8 мм, большой вертел 2.9–3.1 мм, шейка 4.4 мм,
седалищная кость 5.9 мм (график строит `python scripts/figures.py`).

## 4. Модель 3 — сегментация металла

| | |
|---|---|
| Файл | `dxaqc/artifactnet.py`, веса `models/artifact_seg.pt` (19 МБ) |
| Архитектура | та же U-Net с одним выходным каналом — маска металла |
| Обучение | 80 эпох, AdamW `2e-3`, OneCycle; обучающие маски — обведённые инородные тела на 23 снимках плюс синтетические косточки, крючки и клипсы, нарисованные генератором на чистых снимках |
| Инференс | если рядом лежат `artifact_seg_2.pt` и далее, их карты вероятностей усредняются |

Сеть даёт два результата: **контур для врача** на картинке и **площадь маски** как признак для
решающей модели. Сама по себе она даёт AUC 0.89, в паре с правилом top-hat — 0.91.

## 5. Модель 4 — ротация и позиционирование бедра

| | |
|---|---|
| Файл | `dxaqc/hipcrop.py`, `dxaqc/hog.py`, модель внутри `models/decision.pkl` |
| Вход | кроп 128×128 вокруг проксимального отдела бедра |
| Выравнивание | по **оси диафиза, прослеженной по кости** (не по точкам): угол ошибается на 0.25° между разными детекторами против 4.3° при выравнивании по точкам |
| Признаки | HOG: ячейка 16, 9 ориентаций, блоки 2×2 с L2-нормировкой |
| Модель | ExtraTrees: 800 деревьев, `min_samples_leaf = 3`, `max_features = 0.2`, `class_weight = balanced_subsample` |
| Обучение | на кропах по ручной разметке **и** на кропах, поставленных каждым членом ансамбля, — обучающая выборка увеличивается вчетверо и совпадает с тем, что модель увидит в проде |
| Инференс | лес смотрит кроп каждого из трёх детекторов, вероятности усредняются |
| Согласование | вероятность смешивается с вероятностью второго бедра того же исследования с весом 0.2 |

**Почему смешивание с другим бедром.** Оба бедра укладывает один лаборант за один сеанс, и метки
эксперта совпадают чаще случайного: корреляция 0.59, P(плохое | второе плохое) = 0.67 против базовых
0.24. AUC от смешивания почти не меняется, зато оценка перестаёт скакать у порога: F1 0.591 → 0.657.

**Что проверяли и не взяли:** профиль медиального контура («выступ малого вертела», то самое, на что
смотрит врач) — AUC 0.52, контур на таком разрешении неустойчив; мелкая сетка HOG; PCA-сжатие;
бустинг и логистическая регрессия вместо леса; маленькая CNN с нуля; многозадачная сеть «точки +
ротация»; добавление геометрии точек в лес (0.862 против 0.864) и стекингом (0.870 при F1 0.664).

## 6. Модель 5 — пять решающих моделей по типам нарушений

Каждому типу нарушения соответствует своя маленькая модель над 1–3 измерениями (`dxaqc/decision.py`,
класс `Monotone`).

| Тип | Признаки | Направление |
|---|---|---|
| Не выровнена ось позвоночника | угол оси к вертикали, угол оси относительно линии гребней таза, кривизна столба | больше / меньше / меньше |
| Некорректная укладка позвоночника | уверенность сети в гребнях, доля яркой кости в нижних углах кадра | меньше / меньше |
| Посторонние предметы | площадь тонких ярких структур вне столба, площадь маски сегментационной сети | больше / больше |
| Некорректная область интереса бедра | поле снизу, поле сверху (мм) | меньше / меньше |
| Ротация и укладка бедра | вероятность из леса | больше |

**Устройство `Monotone`:** признаки умножаются на знак (+1 — «больше значит хуже»),
стандартизуются, веса подбираются логистической регрессией и **обрезаются снизу нулём** — модель
физически не может выучить, что ровная ось хуже кривой. Дальше — калибровка Платта, но не по самому
счёту, а по его **процентилю** в обучающей выборке: при 6–17 положительных примерах сигмоида,
подогнанная к счёту, гуляет от фолда к фолду, и вероятности из разных фолдов оказываются
в разных шкалах (потеря до 0.12 AUC).

**Пороги.** У каждого типа свой порог, выбранный на максимум F1 внутри обучающей части.
Вторая рабочая точка, `screening`, ставит порог на чувствительность 0.80 по типу и никогда
не бывает строже сбалансированной.

**Синтетические нарушения.** Для двух самых редких геометрических типов (наклон оси — 10 примеров,
область интереса — 7) генератор `dxaqc/synth.py` делает варианты настоящих снимков с известным
нарушением: поворот столба за 5°, обрезка поля бедра сверху, снизу и сбоку. Каждый вариант измеряется
**фолд-моделью, которая не видела исходный снимок**, и добавляется в обучение с весом 0.1 — только
на подбор весов признаков; шкала процентиля, калибровка и порог остаются на настоящих снимках.
Эффект: v_axis AUC 0.871 → 0.882, v_roi 0.874 → 0.892.

**Сборка вердикта.** Снимок некачественный, если сработал хотя бы один тип. Общая вероятность
(`quality_prob`, по ней считается ROC-AUC) собирается как noisy-OR, причём у позвоночника — из
процентилей типов, у бедра — из самих вероятностей, а затем одна калибровка на область сводит обе
шкалы вместе. Без этой калибровки общий AUC падает с 0.88 до 0.75.

## 7. Измерения между сетью и решением (обучения не требуют)

`dxaqc/geometry.py`, `features.py`, `vertebrae.py`:

- угол оси позвоночника к вертикали кадра и он же относительно линии между гребнями таза;
- охват сверху в высотах позвонка: шаг позвонка определяется по профилю яркости столба и работает
  как анатомическая линейка (ТЗ требует «половину тела Th12», а на снимке нет подписей уровней);
- поля кадра бедра в миллиметрах от большого вертела (сверху), малого вертела (снизу) и наружного
  края вертела (сбоку);
- доля яркой кости в нижних углах кадра — проверка гребней по пикселям, не зависящая от сети;
- площадь и длина тонких ярких структур (морфологический top-hat) вне столба позвоночника;
- чтение впечатанной аппаратом разметки и расстояние её разделителей до межпозвонковых промежутков.

Все измерения считаются в миллиметрах с учётом разного шага пикселя по осям.

## 8. Как обучалось

| | |
|---|---|
| Данные | 100 исследований, 252 снимка (99 позвоночник, 153 бедра), один аппарат GE Lunar Prodigy Advance |
| Метки качества | эксперт заказчика: 5 типов нарушений, от 6 до 36 положительных примеров на тип |
| Разметка точек | своя, по схеме `docs/annotation_scheme.md`, инструментом `tools/annotator` |
| Разбиение | StratifiedGroupKFold по исследованию, 5 фолдов, 10 повторов с разными сидами |
| Утечки | снимки одного пациента никогда не попадают одновременно в обучение и в проверку; пороги подбираются внутри обучающей части; синтетика добавляется только в обучающие фолды |
| Дисбаланс | взвешивание классов, монотонные модели, синтетические нарушения для редких типов |

Порядок обучения с нуля — шесть команд в `docs/training.md`, полный цикл около двух часов
на ноутбуке с GPU.

## 9. Как дообучить на новых данных

Три сценария, от самого дешёвого к самому дорогому.

**1. Только пороги и решающий слой** (минуты). Нужны новые снимки с метками качества эксперта.
Сети точек и сегментации не трогаются:

```bash
python scripts/fit_decision.py --synth ens3b --members fix_s100 strong_s100 base_s100
python scripts/eval_pipeline.py --synth ens3b --members fix_s100 strong_s100 base_s100
```

Это же нужно при переносе на другой парк аппаратов: по нашему замеру на чужом денситометре
проверка гребней переносится хуже всего, и перекалибровка порогов — первое, что стоит сделать.

**2. Дообучение детектора точек** (часы). Нужна разметка точек на новых снимках — инструмент
`tools/annotator` и инструкция `docs/annotation_scheme.md`. Дальше обучаются три члена ансамбля,
пересобираются предсказания вне фолдов и решающий слой.

**3. Полное переобучение** (около двух часов) — если сменился аппарат или протокол съёмки.
Порядок в `docs/training.md`: разметка → индекс → классификатор области → три детектора точек →
ансамблевые предсказания → синтетика → сегментация металла → решающий слой → оценка.

Сравнивать между собой имеет смысл только числа из `eval_pipeline.py`: они получены на
кросс-валидации по пациентам, а не на том же наборе, на котором обучались.

## 10. Размеры и время

| | |
|---|---|
| Все веса | 141 МБ (6 сетей точек по 19 МБ, сегментация 19 МБ, решающий слой 5.7 МБ, область 3.6 МБ) |
| Docker-образ | 1.78 ГБ (linux/amd64, CPU-сборка torch; сборка под CUDA — одним аргументом) |
| Скорость | 0.43 с на снимок на процессоре, 0.13 с на GPU; 2.2 с на исследование при лимите ТЗ в 3 минуты |
| Память | пик 1.1 ГБ |
| Минимальная конфигурация | 2 ядра, 2 ГБ памяти, видеокарта не нужна |

Время почти целиком уходит на три сети точек: они считают 128×128 тепловых карт на каждую
из 4 или 9 точек. Это осознанный размен — ансамбль стоит втрое дороже одной сети и даёт
воспроизводимые метрики вместо зависящих от случайной реализации.
