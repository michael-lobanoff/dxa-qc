# Руководство пользователя

Сервис проверяет снимки денситометрии (DXA) поясничного отдела позвоночника и проксимального отдела
бедра и отвечает на один вопрос: годится ли снимок для интерпретации, а если нет — что с ним не так.
Решение остаётся за специалистом; сервис показывает измерения и подсвечивает место нарушения.

## Три способа запуска

### 1. Веб-интерфейс (проще всего)

```bash
docker run --rm -p 8000:8000 --entrypoint uvicorn dxa-qc dxaqc.api:app --host 0.0.0.0 --port 8000
```

Откройте `http://localhost:8000`, перетащите файлы `.dcm` или один `.zip` и нажмите «Проверить».
Появится таблица с вердиктами; щелчок по строке открывает снимок с подсветкой нарушения.
Кнопка «Скачать CSV» сохраняет результат.

### 2. Командная строка (пакетная обработка)

```bash
python scripts/predict.py <папка_или_архив.zip> --out outputs/results.csv --vis outputs/vis
```

На выходе `results.csv` и `results.xlsx`, а с ключом `--vis` ещё и папка с картинками плюс архив
`results_vis.zip`. Для каждого снимка сохраняются три файла: PNG с подсветкой, DICOM Secondary
Capture (дополнительная серия для PACS) и DICOM SR — текстовый отчёт о находках.

### 3. HTTP API (для встраивания)

```bash
curl -X POST "http://localhost:8000/predict?format=csv" -F "files=@study.zip" -o results.csv
```

Полное описание методов — в `README.md` и на `http://localhost:8000/docs`.

## Как читать результат

Одна строка — одно изображение.

| Колонка | Что означает |
|---|---|
| `anatomical_region` | «Поясничный отдел позвоночника» или «Проксимальный отдел бедра» |
| `quality_class` | 0 — снимок качественный, 1 — есть нарушение |
| `violation_type` | какие именно нарушения, через «; »; пусто, если нарушений нет |
| `quality_prob` | вероятность нарушения от 0 до 1 — насколько сервис уверен |
| `details` | измерения: угол наклона оси, охват в позвонках, поля кадра в миллиметрах |
| `processing_status` | `Success` или `Failure` (файл не прочитался — причина в колонке `error`) |
| `time_of_processing` | секунды на этот снимок |

### Что означает каждое нарушение

**Позвоночник**

- **«Некорректная укладка»** — в кадр не попали верхние края подвздошных костей снизу либо не хватает
  захвата сверху (по критерию ТЗ нужно дойти до середины тела Th12). В `details` видно, сколько
  высот позвонка укладывается между линией гребней и верхним краем кадра: нормально 4.5 и больше.
- **«Не выравнена ось позвоночника»** — угол между осью позвоночного столба и вертикалью больше
  допустимых 5°. Точное значение — в `details`.
- **«Присутствуют посторонние предметы»** — на снимке найдены тонкие яркие структуры вне
  позвоночного столба: чаще всего косточки бюстгальтера, застёжки, клипсы. На картинке они обведены.

**Бедро**

- **«Некорректная укладка»** — нога развёрнута неправильно. Основной признак — малый вертел:
  при правильной ротации он едва виден, при недоротации выступает, при переротации исчезает.
- **«Некорректная область интереса»** — вокруг исследуемой области мало места: по критерию ТЗ нужно
  3 см над большим вертелом, 3 см под малым вертелом и 2 см сбоку. Фактические поля — в `details`.

### Особые ответы

- **эндопротез** — бедро с металлическим протезом оценивается как любое другое (так решили
  организаторы, Q&A 17.09): укладка и поля кадра — задача лаборанта и при протезе. В `details`
  добавляется пометка «эндопротез».
- **«оценка не проводится: …»** в `details` (код `unsupported`, `violation_type` пустой) — изображение
  не похоже на денситометрию позвоночника или бедра (пустой кадр, не рентген, другая анатомия).
  Сервис честно отказывается, вместо того чтобы выдать вердикт наугад. Столбец `violation_type`
  содержит только названия нарушений из словаря организаторов.
- **«на снимке впечатана разметка аппарата…»** — денситометр напечатал поверх снимка свои рамки
  L1–L4. Их линии неотличимы от металла, поэтому инородные тела на таком снимке не оцениваются.

## Режим проверки

В веб-интерфейсе рядом с кнопкой «Проверить» есть выбор режима, тот же переключатель доступен в API
(`?policy=…`) и в командной строке (`DXAQC_POLICY=…`):

- **сбалансированный** (по умолчанию) — порог каждого типа настроен на максимум F1. Именно в этом
  режиме измерены метрики в README;
- **скрининг** — пороги настроены так, чтобы находить 80 % нарушений каждого типа, и никогда не строже
  сбалансированных: этот режим может только добавить находки. Пропусков меньше (чувствительность по
  снимкам 0.92 против 0.86, по исследованиям 0.94 против 0.92), ложных тревог больше (специфичность
  0.72 против 0.82).

Таблицу результатов можно отфильтровать («только с нарушениями») и отсортировать по вероятности —
удобно, когда загружен целый архив.

## Как читать картинку

Подписи на картинке — те же формулировки, что в таблице: «Вердикт: Некорректная укладка (вероятность
0.87)», измерения в миллиметрах и градусах.

- **голубая линия** — ось позвоночника, **белая** — вертикаль для сравнения;
- **зелёные кружки** — верхние края подвздошных костей, **зелёные чёрточки** — тела позвонков;
- **жёлтые стрелки** на бедре — измеренные поля кадра до краёв;
- **красный контур** — найденное инородное тело;
- в шапке — область, измерения и вердикт с вероятностью.

## Рабочая точка: чувствительность против ложных тревог

По умолчанию сервис настроен «не пропустить брак»: находит около 83 % нарушений, но примерно каждое
третье нормальное исследование помечает для перепроверки. Если ложных тревог слишком много:

```bash
DXAQC_POLICY=balanced python scripts/predict.py ...
```

Тогда порог ставится по максимуму F1: меньше тревог, но и пропусков больше.

## Чего сервис не делает

- не ставит диагноз и не измеряет минеральную плотность — только контроль качества укладки;
- не выявляет патологию (сколиоз, переломы) — только отмечает эндопротез в пояснениях;
- «сколиоз» не считается нарушением укладки (эксперт в обучающих данных его так и не помечал);
- обучен на одном аппарате (GE Lunar Prodigy Advance); на снимках другого производителя проверяйте
  результат выборочно — сервис для этого сообщает, когда изображение не похоже на обучающие.

Все расчёты идут локально: изображения никуда не передаются.
