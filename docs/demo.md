# Демонстрационный сценарий

Требование ТЗ 7.2: вместе с решением сдаётся презентация **и демонстрационный сценарий**. Здесь он
целиком: что запустить, что показать, что при этом говорить и что делать, если что-то не поднялось.

Всё выполняется локально. Медицинские изображения никуда не передаются — это требование ТЗ 3.2
(«без передачи медицинских изображений во внешние системы»), и именно поэтому публичного стенда
с загрузкой чужих снимков у решения нет и не должно быть.

## Подготовка (один раз, до защиты)

```bash
git clone git@github.com:michael-lobanoff/dxa-qc.git && cd dxa-qc && ./run.sh build
```

Сборка занимает 5–10 минут и нужна один раз. Проверка, что всё живо:

```bash
./run.sh serve
```

Сервис поднимается на `http://localhost:8000` — веб-интерфейс, `http://localhost:8000/docs` — Swagger.

**Положите рядом три-четыре файла для демонстрации** (данные организаторов, в репозиторий они
не входят): один позвоночник с посторонним предметом, одно бедро с ротацией, одно качественное
бедро, один «битый» снимок с обрезанным полем.

## Сценарий А. Веб-интерфейс — 60 секунд, основной для защиты

| Шаг | Действие | Что сказать |
|---|---|---|
| 1 | Перетащить три файла DICOM в окно, нажать «Проверить» | «Исследование — три снимка, обработка занимает полторы секунды» |
| 2 | Показать таблицу: область, вердикт, тип нарушения, измерения | «По каждому снимку — не только вердикт, но и измерение, по которому он вынесен: наклон оси один градус, поля сорок четыре миллиметра» |
| 3 | Щёлкнуть строку с посторонним предметом | «Красным обведено то, из-за чего снимок помечен: тонкая яркая дуга поверх ребра — это косточка белья, ровно как на рисунке три в ТЗ» |
| 4 | Показать легенду под снимком, пролистать стрелкой к следующему | «Голубым — точки и предложенные зоны измерения, жёлтым — поля кадра. Соседние снимки листаются стрелками» |
| 5 | Переключить режим на «скрининг», нажать «Проверить» ещё раз | «Вторая рабочая точка: ловит больше брака ценой ложных тревог. Лаборатория выбирает сама» |
| 6 | Нажать «Скачать CSV» | «Тот же результат выгружается таблицей в формате ТЗ» |

## Сценарий Б. Пакетная обработка — если спросят про поток

```bash
./run.sh predict /путь/к/архиву.zip ./outputs
```

На выходе `outputs/results.csv` и `.xlsx`, а с ключом `--vis` — ещё и папка с картинками, DICOM
Secondary Capture и DICOM SR по каждому снимку плюс zip-архив рядом.

Что показать: последнюю строку вывода — «499 images, 499 processed, 0 failed, mean time 0.43s».
Что сказать: «Весь архив организаторов — 499 файлов, ни одной ошибки, полторы минуты».

## Сценарий В. API — если спросят про встраивание

```bash
curl -X POST "http://localhost:8000/predict?format=csv" -F "files=@study.zip" -o results.csv
```

Swagger с описанием всех четырёх методов — `http://localhost:8000/docs`. Спецификация лежит
в репозитории (`docs/openapi.json`), её можно посмотреть и не запуская сервис.

Методы: `GET /health` (какие модели загружены), `POST /predict` (json / csv / xlsx / zip),
`POST /analyse` (строки плюс картинка в base64 — этим пользуется веб-интерфейс),
`POST /predict_folder` (пакетная обработка примонтированной папки).

## Кейсы, которые стоит показать

1. **Косточка белья.** Выглядит как ребро, а сервис обвёл тонкую яркую дугу поверх ребра.
   Признак на этом снимке выше, чем у всех 82 чистых снимков обучающей выборки — то есть это
   различимый сигнал, а не случайность.
2. **Битый снимок.** Бедро попало в кадр частично: в полях стоят прочерки, а не выдуманные
   миллиметры, вердикт — «некорректная область интереса; некорректная укладка».
3. **Чужой снимок.** Обычная рентгенограмма поясницы: «оценка не проводится, размер пикселя
   0.14 мм — это не денситометрия». Отказ вместо вердикта наугад.
4. **Снимок с впечатанной разметкой аппарата** (внешний набор): сервис читает рамки и предлагает
   сдвинуть разделитель уровней, специалист принимает или отклоняет предложение.

## Если что-то пошло не так

- **Не поднимается Docker** — сервис работает и без него: `python3 -m venv .venv &&
  .venv/bin/pip install -r requirements.txt && .venv/bin/pip install -e . && .venv/bin/uvicorn dxaqc.api:app`.
- **Нет интернета на площадке** — образ и веса локальные, внешние обращения не нужны совсем.
- **Нет времени на живой запуск** — показать запись экрана и готовые результаты прогона
  (`outputs/results.xlsx` и картинки из `--vis`).
